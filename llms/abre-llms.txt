# Abre

> Abre is a K-12 education data platform (Cincinnati, Ohio; founded 2017) that consolidates student,
> staff and operational data from a district's student information system and EdTech tools into one
> role-based interface built around a Student360 learner profile. Abre is a CONSUMER of education
> APIs, not a publisher of one: as of 2026-09-06 it publishes no developer portal, no API reference,
> no OpenAPI or other machine-readable contract, no SDKs, no webhooks, and no MCP or agent surface.

Generated by API Evangelist from the public Abre surface on 2026-09-06. Abre serves no /llms.txt of
its own — the path returned 404 on abre.com, www.abre.com, help.abre.io, marketplace.abre.com and
discover.abre.com, and an HTML holding page on platform.abre.io.

## Integration surface — the APIs Abre CONSUMES

Abre ingests district data through five documented rostering paths. All are inbound; none is an
endpoint Abre serves.

- [How Abre Syncs with Student Information Systems](https://help.abre.io/hc/en-us/articles/4402074039195-How-Abre-Syncs-with-Student-Information-Systems): The five methods, compared.
- [Integration Guide: OneRoster 1.1 API](https://help.abre.io/hc/en-us/articles/34378897490075-Integration-Guide-OneRoster-1-1-API): Abre calls the district SIS as a 1EdTech OneRoster 1.1 REST client using OAuth 2.0. The district hands Abre a BaseURL, AuthURL/TokenURL, ClientID and ClientSecret over SFTP. Syncs students, staff, schools and classes only.
- [Integration Guide: OneRoster Zip Files](https://help.abre.io/hc/en-us/articles/34380006988827-Integration-Guide-OneRoster-Zip-Files): OneRoster bulk CSV/ZIP dropped on an Abre SFTP location.
- [Integration Guide: ClassLink](https://help.abre.io/hc/en-us/articles/34368801953179-Integration-Guide-ClassLink): ClassLink OneRoster roster provisioning plus ClassLink SSO.
- [Integration Guide: SchoolDay (GG4L)](https://help.abre.io/hc/en-us/articles/34376981400987-Integration-Guide-SchoolDay-GG4L): GG4L School Passport data exchange.
- [Integration Guide: Automated SIS Integration](https://help.abre.io/hc/en-us/articles/34381325960219-Integration-Guide-Automated-Student-Information-System-Integration): Nightly templated file transfer over SFTP for demographics, attendance, behavior and grades — the data OneRoster 1.1 does not carry.
- [Getting Started with SFTP Data Uploads](https://help.abre.io/hc/en-us/articles/22581602912155-Getting-Started-with-SFTP-Data-Uploads)
- [3rd Party Assessment Data Integration Setup](https://help.abre.io/hc/en-us/articles/4417348892443-3rd-Party-Assessment-Data-Integration-Setup) and [what can be integrated](https://help.abre.io/hc/en-us/articles/4416471611547-What-3rd-Party-Assessment-Data-can-be-Integrated-with-Abre): NWEA MAP, iReady and others.
- [Single Sign On](https://help.abre.io/hc/en-us/articles/24453565655195-Single-Sign-On): OAuth 2.0 SSO with Google, Microsoft, Apple, ClassLink, Clever, GG4L and Facebook.

## What is absent, and verified absent

- No OpenAPI, Swagger, GraphQL SDL, AsyncAPI, WSDL or .proto at any probed path on any Abre host.
- No /.well-known document of any kind — security.txt, openid-configuration, oauth-authorization-server, oauth-protected-resource, api-catalog, ai-plugin.json, ucp.json, acp.json, aauth-resource.json, apis.json and agent-card.json all returned 404.
- No A2A agent card at either /.well-known/agent-card.json or the legacy /.well-known/agent.json.
- No MCP server, hosted or stdio.
- No first-party SDK on npm, PyPI or any other registry; the GitHub org has no public repositories.
- No published rate limits, no webhooks, no changelog, no CLI, no sandbox, no bug bounty or vulnerability disclosure policy.
- auth.abre.io answers HTTP 200 with the same 40-byte body "Please provide authentication parameters" for every path, including a negative control that cannot exist. Treat every 200 from that host as meaningless.
